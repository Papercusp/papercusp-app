The system · answers ②

Five shapes, one meaning each

Before choosing a layout, fix the grammar. Every element in the popup is one of five kinds. Each kind gets a form you can identify without reading the label — shape, border, corner radius, and case all carry the distinction, so it survives a greyscale screenshot and a colour-blind operator.

Specimen sheet the vocabulary all three directions use
KindMeansFormSpecimen
State A fact. Read-only. Changes on its own. Full-round pill, no border, tinted fill, lowercase. live ctx 83%
Mode A state you can change. A switch that is currently on. Pill with a filled cap + caret. Cap on = enabled, grey = off. AUTOon ▾ IDEATEoff ▾
Action Happens the instant you click it. Rectangle, 4px radius, 1px border, icon + Sentence case.
Action → picker Opens a chooser first. Nothing happens yet. Same rectangle, plus a trailing ….
Alert A state that is also a link to its detail. Warn-tinted pill with a trailing ›.
Field Part of a form. Nothing happens until you submit. Recessed well with an inset shadow and a caption above it.
Plan Select plan… ▾
Members 3

Two rules fall out of the table, and they do most of the work.

① Rounded = the system is telling you something. Rectangular = you are telling the system something. Once that holds, you never have to ask whether a thing is clickable-to-change or merely true.

② A trailing … means “a chooser opens”; no ellipsis means “it fires now”. Focus window acts; Grade session… asks first. That one character removes the “I clicked Grade and nothing happened” class of confusion entirely.

Your question 2 · read from the source, not from memory

What the rail is missing

I diffed OrientResult (agent-tools/coordination/tools/orient.ts, 24 fields plus 10 handler folds) against AgentDetail (adv-agent-detail.ts) and the roster entry the rail already reads. One gap dominates everything else.

The rail shows what the agent is doing and holding. It shows nothing about what the agent has been told.

Locks, files, claims, coord, events, loop, context — all of it is behaviour. But an agent's behaviour is driven by standing orders it received outside the conversation: facts folded verbatim into its every orient, registered modes and who set them, and the resolved instructionPrecedence that says which generic rules are suppressed right now. None of that is visible anywhere in the popup — and unlike everything else in the rail, you cannot recover it by reading the transcript, because it never appears there. It arrives in the agent's system context.

Your question 1 · the rest of the coord surface

Yes — and one of them is a live bug in this popup

Past orient, the coord:* plane has 57 tools. Six carry per-agent state the rail has no way to show. One of them undermines the popup's own composer.

coord:wake-mode — an agent can be in manual mode, where wakes are staged for the owner to release rather than delivered.

This popup's composer sends a coord:send with wake: 'required'. Send a message to an agent in manual wake-mode and the popup reports “Sent — the agent is woken if it's live” — but the wake is sitting in a staging queue, undelivered, and the agent is not working on what you just asked. The banner is not lying, exactly; it says if it's live. It simply cannot see the one state that makes the send a no-op.

Wake-mode belongs in the header next to liveness, and the composer should say “Staged — release it to deliver” rather than “Sent” when the agent is manual. That is a correctness fix, not a visual one, and I'd do it whichever direction you pick.

The carry brief

This is the richest thing you asked about, and it already has a fully-formed shape in the code: CarryBrief (carry-brief.ts) and CompactionRecovery, the block afterCompaction: true returns. It is the agent's working memory made durable — and none of it reaches the popup.

Staleness is the whole point of this data, and it is the part with no visual form yet.

Three fields exist purely to date the carry — checkpointUpdatedAtMs, carryNoteUpdatedAtMs, postNoteInbox — plus citedRefs, which the code calls “the #1 stale-conclusion tell”: a work-item the note cites that has since changed state. A checkpoint written 40 minutes and a dozen turns ago is nearly worthless, and the model already knows that. So in the panel, the age is rendered as loudly as the content — not as a muted timestamp in the corner.

And its severity is conditional. A cold-carry agent rebuilds from its checkpoint on every wake — the checkpoint is its memory, so a stale one is critical. For a warm agent the same staleness is merely unhelpful. Same number, different colour, decided by control.carry.

Why left, and why this split

  • The order is causal. Orders → conversation → activity. The left panel explains the middle; the right panel is its consequence. Two rails on the same edge would just be a longer scroll with a divider.
  • The two panels change at completely different rates. Orders shifts when a mode flips or a fact is asserted — minutes to days. Activity shifts every turn. Putting slow and fast content in one column is what made the current rail feel like a wall.
  • It answers a question the popup currently cannot. “Why is this agent doing that?” is a left-panel question and there is nowhere to look for it today.
  • Left collapses first on a narrow window — it is the more static side, so losing it costs least. Both toggles are nuqs, so a link can open an agent with exactly the panels you want.

Cost and the honest caveats

  • Width. 272 + ~560 + 300 ≈ 1140px, so the modal grows to min(1240px, 96vw) with both open. Fine on a desktop; on anything narrower one panel overlays as a drawer, which the modal already does for the existing rail.
  • This is the largest data-layer addition in the whole redesign. getAgentDetail gains carry-brief, walls, wake-mode, goal and precedence legs. Every source is durable and per-agent — but it is real server work, not restyling.
  • Some of it is only written if the agent bothered. A carry-note or checkpoint exists because the agent wrote one. An empty Carry section is itself a finding — but the panel must say “never written”, never render blank, or it repeats the exact failure the dossier's unavailableSignals was added to prevent.
  • I'd build it after D + R1 land, as its own phase.
