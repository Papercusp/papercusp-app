Harness templates

A harness template is a recipe for spinning up a new project. It bundles the role prompts, the orchestrator’s decision logic, the default plugin set, and any seed files needed to start a mission. Installing a template creates a fresh project directory wired to run.

Templates are how you turn “this kind of harness” into something shareable. The reference templates that ship with Papercusp — coding, briefings, org — are themselves just templates published to the marketplace.

Manifest fields

Section titled “Manifest fields”

The minimum:

harness_kind sets the family (coding, org, business, etc.) so the operator knows which UI affordances to surface. topology is single or multi (multi-harness templates spawn sub-harnesses on install).

requires lists plugin slugs the template depends on. The CLI installs those plugins automatically as part of papercusp install <template>.

Authoring workflow

Section titled “Authoring workflow”

papercusp publish does a final secret scan, signs the tarball (Ed25519), uploads it to the marketplace, and writes the resulting slug+version to a sidecar so papercusp retract can roll it back later.

Submitting to the marketplace

Section titled “Submitting to the marketplace”

The first publish under @your-handle/... triggers GitHub-OAuth: prove ownership of the GitHub user, get a service token, future publishes under that scope use the token. See the Authors page for the full flow.

(Screenshot: the GitHub OAuth flow from papercusp publish.)

After publish:

  • Listed in the Templates marketplace.
  • Operators can install yours via the UI’s “Install” button.
  • You can papercusp retract --action deprecate --reason "..." to flag a version as deprecated; it stays installable but warns on use. Use withdraw to refuse new installs entirely, or yank to pull a specific version.

Tips

Section titled “Tips”
  • Keep prompts terse. Long prompts cost more tokens and are harder for agents to follow. Reference the reference templates for proven shapes.
  • Use requires aggressively. A template that depends on @papercupai/cloudflare-pages-hosted should declare it; users shouldn’t have to manually enable plugins after install.
  • Test against papercusp doctor. If your template needs ffmpeg or gh or any other binary, declare it in .papercusp/config.json#requires.binaries so the operator surfaces a pre-flight warning.
  • Version conservatively. Per the migration story, a major bump means you’ve broken existing harnesses on this template. Operators with ^0.1 pinned will refuse to upgrade.
