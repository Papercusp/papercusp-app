# Revisions
URL: /internal/docs/snapshots/revisions

Mapping from each review item across the two rounds of feedback to the section that addresses it (or to the deferred bucket with reasoning). Future readers ask "why is X complicated" — the answer lives here.

import { Aside } from '@astrojs/starlight/components';

This page is the round-by-round design-review record for the snapshots V1
design as it stood in May 2026. It is **not** a description of shipped
behavior. Since these reviews, much of the build-script / OAuth substrate
*was* implemented (`packages/operator-core/lib/provision/` and
`/oauth/`), and the separately-scoped snapshot-**export** subsystem was
later **retired** (`@papercusp/export-state`, the `snapshots:*` tools, and
the `kind=snapshot` Cupboard were dropped — see
`retire-snapshots-instance-spec-2026-06-09`, migration 199). Several
decisions below were superseded during implementation; the most
load-bearing divergences are flagged inline. Where this log and the code
disagree, **trust the code.**

This page tracks the substantive design decisions made during review. Each
item links back to the review prompt that surfaced it and forward to the
section that addresses it (or to the deferred bucket with the reasoning).

The plan went through **six rounds of external review** before
implementation. Each round's reviewer was rigorous; their feedback is
preserved here verbatim in summary so future readers can audit the design
rationale. A seventh sign-off review was planned before implementation; the
"implementation begins" framing below is preserved as the historical
record (see the banner above).

## Round 2 (2026-05-08)

The second-round reviewer concurred with the round-1 inclusions but
pushed back substantively on two points and refined four others. The
substantive pushbacks are reflected in the plan; the refinements landed
without further debate.

| Review item                                                        | Resolution                                                                                                                                                                                                                                                                                                                                                    | Section                                                                      |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| **A. Sandboxing-only-for-unsigned is a misapplication of signing** | **Fully conceded.** event-stream and xz-utils were the right examples — *signed* code can be malicious. Signing proves provenance, not safety. Sandbox is now default for *all* scripts; signing affects only consent-UI presentation, the visibility of the "trust this publisher" toggle, and the friction of escaping the sandbox as a power-user opt-out. | [build-scripts § Sandboxing](./build-scripts#sandboxing-and-the-trust-model) |
| **B. "Cost estimate with disclaimer" compromise is theater**       | **Fully conceded.** The compromise was the worst option — looks like a feature, behaves like a comment. See Round 1 "Audit log retention" above.                                                                                                                   | [build-scripts § Audit logging](./build-scripts#audit-logging)               |
| **D. ## Pattern observations across rounds

Every round added 3–6 substantive items that were genuine gaps. The
gaps got smaller as rounds progressed:

* **Round 1**: structural issues (idempotency contract, sandbox model, schema evolution, secret-shareable case)
* **Round 2**: substantive refinements (sandbox/signing conflation, cost theater, audit retention)
* **Round 3**: implementation-level holes (macOS asymmetry, IMDS/RFC1918, scriptHash comparison, marketplace moderation overconfidence, trust granularity)
* **Round 4**: targeted gaps (smoke test, dev escape, ownership transfer, PG lock)
* **Round 5**: surgical refinements of round 4 (Tauri sidecar, region templating, recordResource helper, key rotation, queue overflow)
* **Round 6**: refinements of round 5 (named dev path, preset maintenance, teardown dispatcher, key-rotation attestation)

Convergence is happening. Round 7 should be sign-off-only. If it
surfaces substantive new issues, scope is re-evaluated.
