# Managed script execution parity and native disable gates
URL: /internal/docs/agent-insights/managed-script-execution-parity-and-disable-gates

Source- and probe-grounded inventory for Codex functions.exec, Claude Code, OMP eval, and Papercusp code:run, with the P-017 parity checklist required before D-017 disables native script engines.

# Scope and target

This closes P-025 under D-013/D-017 and extends [the command parity matrix](/internal/docs/agent-insights/managed-command-execution-parity-and-break-glass) to model-facing script engines. `code:run` is the primary managed engine; Codex `functions.exec` is only a direct-call compatibility door. Native script engines remain enabled until P-017 proves the gates below, steering and telemetry ship, and the local break glass is tested. The 2026-08-22 inventory covers Claude Code 2.1.240, Codex CLI 0.149.0, OMP 17.3.5, and current Papercusp staging.

# P-017 parity-test checklist

D-017 may disable native script execution only after one automated, client-neutral suite proves:

1. positive/negative launch and resume controls for every supported version, including Codex's visible denial and OMP allowlist omission;
2. isolation from host modules, environment, filesystem, network, credentials, and native commands outside projected capabilities;
3. current authorization, recipe revision/authority revalidation, recursive-call denial, and fail-closed stale bindings;
4. bounded fan-out, deterministic order, all-settled isolation, mixed read/write accounting, per-child telemetry, and no orphans;
5. cancel before dispatch, during nested work/write, and during synchronous compute; timeout classification; child teardown; uncertain-write truth;
6. JSON summary plus valid image/audio, malformed MIME/base64, multiple blocks, size limits, and no intermediate-media leak;
7. server PTY create/input/resize/incremental-read/exit/cleanup, carry/restart reattach, permission denial, and no native fallback;
8. durable background identity, persisted recipe/script revision and inputs, task-manager enrolment, completion event, exactly-once wake, expiry, kill, reattach, and terminal replay;
9. thrown vs semantic vs bulk-partial errors, deterministic branch attribution, idempotency-gated retries, and no duplicate write after timeout/lost result;
10. intermediate and authored-summary accounting, aggregate result-door enforcement, stable spill references, selective expansion, and native-byte exclusion;
11. explicit replay state across warm/cold carry and operator restart, without client-isolate or OMP-kernel memory;
12. teaching denials naming `code:run`, `recipes:*`, and capability tools, plus telemetry for client/version, disable state, native attempt/denial, server usage, failures, spill, cancel, background wake latency, and break glass;
13. operator-down and deploy-restart break-glass drills, followed by proof that normal managed resume restores the deny.

P-011 is a hard prerequisite wherever this list names PTY/session lifecycle or durable background hand-off. A green script-worker unit test alone is not a D-017 verdict.

# Break glass and rollout

Extend P-024's single local, session-scoped recovery path. Claude restores no separate script engine. Codex restores `code_mode_host=true` only for the bounded session and restores `shell_tool` separately only if required. OMP adds only `eval` to its explicit allowlist; Bash remains a separate P-024 surface. The local audit record names client/version, session/owner, cwd, reason, time, and every restored native surface. Normal wake/resume re-arms the deny.

Rollout order: break glass and drills; P-011 PTY/background prerequisites; P-005 security/replay contract; P-017 green parity; steering and teaching denial; adoption/native-attempt telemetry; canary; managed default disable. Human-owned unmanaged terminals remain outside D-017 unless explicitly enrolled.
