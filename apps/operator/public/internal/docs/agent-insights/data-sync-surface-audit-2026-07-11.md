# Operator data-sync surface audit (2026-07-11)
URL: /internal/docs/agent-insights/data-sync-surface-audit-2026-07-11

A route-by-route audit and completed migration of the operator app's durable server-state reads to @papercusp/sync, including the focused Conversations list/detail model, scoped push invalidation, and the stream/probe/search/config exceptions that intentionally remain outside the cache.

## Verdict

The audit found **13 active migration families** plus two mixed-path cleanup
cases. All are now migrated. Durable Postgres-backed reads use the shared root
`@papercusp/sync` cache; write seams invalidate the affected named queries; and
the table-to-query bridge covers out-of-process changes. REST remains only for
mutations and for the explicit stream/probe/search/config exceptions below.

The Advanced → Conversations tab is no longer one of the exceptions. Its Q\&A,
deliberation, agent-chat, message, and unified-inbox reads now use focused named
queries. The unified inbox composes the same four cached lists that the source
views use, so navigation reuses cache entries instead of starting an unrelated
four-store aggregate request.

## Audit scope and test

Scope is the live operator product: `apps/operator/app/**` and
`apps/operator-vite/src/**`. Vite imports the first tree, so treating them as
separate apps would miss real surfaces. `operator-docs`, publishing utilities,
the marketplace registry, and static/public sites are separate applications
without the operator's Postgres sync provider and are not counted as operator
violations.

A read is a violation when all of these are true:

1. it is durable server state shown as application data;
2. its source is Postgres, or already has a named resolver/invalidation path;
3. the UI owns an independent `fetch`/poll/cache instead of the root
   `@papercusp/sync` cache; and
4. it is not an inherently streaming, user-triggered, or operating-system
   observation.

POST/PATCH/DELETE calls are not violations. The sync framework is the read and
cache-coherence path; mutations may remain REST/tool calls as long as the write
seam invalidates the affected named query immediately and the database-change
bridge covers out-of-process writes.

## Reads that should stay outside the data-sync cache

These are not violations. Migrating them to a Postgres named-query cache would
either add no coherence or make a true stream/probe less correct.

| Exception class                                       | Current surfaces                                                                                                                                                                   | Why it should stay                                                                                                                                                                                                                                                                          |
| ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Token, audio, terminal, command, and thinking streams | `OperatorPanel` scan stream, `OperatorConversationProvider` generation/voice transports, `PiPanel` PTY, `TerminalTab`, `AgentThinkingStream`, `CommandCard`, voice bridges         | The incremental event sequence is the product. SSE/WebSocket/IPC is the source; React Query invalidation would collapse ordering and partial output. Durable transcript rows may still have a parallel sync query.                                                                          |
| Runtime/process gauges                                | `FleetRateControl`, hook health on `/coord`, `VersionBadge`, `UpdateChip`, `EnvSwitcherBar`, setup status steps, local-model/embedded-PG/process/Git/backup probes, dev right rail | These observe processes, sockets, binaries, Git, or the host filesystem. No database row change can invalidate them reliably. Visible-only polling with abort/supersede is appropriate until the runtime exposes a dedicated push event.                                                    |
| Deploy/frame/VNC state                                | `AdvFramesTab`, `FrameScreenTrackView`, `FrameVncView`                                                                                                                             | Frame output and VNC are external/runtime streams. Retain SSE plus a low-rate drift-repair poll where the producer can miss a disconnect.                                                                                                                                                   |
| Filesystem and computed developer tools               | Dev Routes/Tables/SQL/PG/Processes/Studio/Backups/Audit tabs, harness testing-domain/file discovery, Git graph, prompt studio, acceptance runner commands                          | These are inspectors or on-demand computations over arbitrary files/processes/tables. A fixed named schema would be misleading. Database-backed subpanels such as Acceptance assertions are called out separately above.                                                                    |
| User-triggered search, export, preview, and discovery | Global/user/transcript/GitHub/Cupboard searches, eval exports, TTS preview, ElevenLabs voice/catalog and subscription lookups, wiki backlinks                                      | They run on explicit input and are not standing server-state subscriptions. Backlinks is a filesystem grep at view time. Cache locally by request if useful, but do not attach database invalidations.                                                                                      |
| Authentication, setup, and security workflows         | Login, auth/me bootstrap, password change, API keys/credentials, OS permissions, telemetry consent, mobile pairing, trust/P2P, publishing and backup actions                       | Most are one-time gates or sensitive commands. Re-read after the mutation or on navigation; do not put secrets or session negotiation in the general sync cache. A future non-secret `auth.currentUser` identity projection is reasonable, but it is not required for page coherence today. |
| Plugin runtime and manifests                          | Settings/Installed plugin runtime, permissions manifest, provisioning, plugin tools                                                                                                | The authority is the plugin host/manifest filesystem and live runtime. ## The durable Conversations boundary

The durable fix is not a faster aggregate endpoint. It is a cache/invalidation
boundary that matches what the user can select:

* one bounded list key per source;
* one ID-scoped detail key per selected row;
* one shared root QueryClient across navigation;
* cache-preserving refresh/invalidation instead of blank-and-reload;
* source-table bridges that invalidate the narrowest safe keys;
* no request-owned selection state, so a late response cannot change which
  conversation the user is viewing; and
* a unified view composed from the source list caches, not a fifth data path.

This is the Work Queue pattern applied to Conversations: server state has one
shared cache, writes emit push invalidations, and URL/local UI state decides
what is visible without becoming another copy of the data.
