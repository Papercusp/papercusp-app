# Managed command execution parity and native-tool break glass
URL: /internal/docs/agent-insights/managed-command-execution-parity-and-break-glass

Source- and probe-grounded parity matrix for Claude Code, Codex, and OMP native command tools versus the Papercusp capability execution family, including disable controls, rollout gates, and operator-down break glass.

# Scope and controlling target

This document closes P-024's command-tool inventory under D-012, D-013, D-016, D-022, and D-023. The target is one managed route: command execution goes through the server-side `capability:*` family. Native client command tools stay available until parity is proved, steering and adoption telemetry ship, and the break-glass path below is implemented and tested. Codex `functions.exec` and other script runtimes belong to P-025/D-017, not this command-only matrix.

The compared client builds were probed on staging on 2026-08-22: Claude Code 2.1.240, Codex CLI 0.149.0, and OMP 17.3.5. The Papercusp column is the current staging implementation, not a planned ideal.

# Required parity tests before native disable

The native command tools remain enabled until an automated, client-neutral suite proves all of the following against the real server route:

1. cwd resolution, required environment propagation, secret redaction, and invalid-cwd errors;
2. foreground stdout/stderr ordering, binary/UTF-8 boundaries, large-output spill references, and aggregate result-door accounting;
3. background launch, durable task-id reattachment after carry and operator restart, completion event delivery, and exactly-once managed-turn wake;
4. PTY create, input, resize, incremental output, exit, and session cleanup;
5. request abort, timeout, explicit kill, process-tree death, repeated kill, and already-exited behavior;
6. sandbox filesystem, credential, network, namespace, and fail-closed/degradation telemetry for the selected production posture;
7. role/effect denial, no-prompt unattended behavior, typed teaching errors, and no fallback to a native client tool;
8. output-cap enforcement and honest exclusion of bytes that never cross the Papercusp result door;
9. one positive and one negative disable control for every supported client build, repeated on resume/wake so native tools cannot silently return;
10. operator-down and release-restart break-glass drills described below.

# Break glass must ship first

Native tool removal makes the operator a command-execution dependency. If `:3070` is down, restarting for a deploy, or unable to serve MCP, the normal capability route is intentionally unavailable. A break glass that itself calls the operator is not a break glass.

Implement one explicit, session-scoped launch option on the existing local launch surfaces, for example `--native-exec-break-glass`. It must be parsed locally by `psu`/the managed launcher before contacting `:3070` and render only to the existing client controls:

* Claude: omit the Bash/TaskOutput/TaskStop hard denies for that launch while retaining unrelated safety denies;
* Codex: set `features.shell_tool=true` for that launch;
* OMP: add only `bash` to the explicit native allowlist rather than restoring every built-in.

The option is never inherited silently. Resume and wake re-arm the normal disable unless the break-glass authorization is explicitly carried for the same bounded session. The client receives a loud system message and terminal banner stating that native execution is active, why, and that capability telemetry/output accounting does not cover those bytes.

Activation must create a durable local append-only launch record before the model starts: session/owner id, client/version, cwd, reason, timestamp, and the exact native surface enabled. When the operator is reachable the record is written through the normal audit surface; when it is not, the launcher retains the record outside the repository and replays it after recovery. The record is evidence, not an authorization dependency. Never put the offline spool in the shared git tree.

Two drills are mandatory:

1. **Operator-down bootstrap:** stop or make `:3070` unreachable; launch a managed recovery session locally with the explicit break-glass option; prove one diagnostic command and the sanctioned operator restart path work; restore the operator; prove the local record is ingested; end the session; prove a normal relaunch has no native shell.
2. **Deploy-restart window:** before triggering a release action that restarts `:3070`, establish one bounded release-driver session with break glass; prove it remains able to inspect/recover the service while MCP is unavailable; after health returns, terminate the driver and prove all ordinary managed sessions remain native-disabled.

Do not keep a permanently native-enabled hidden agent. Do not make the break glass a default-off server flag that cannot be read while the server is down. Do not silently treat an operator-supplied `AGENT_CMD --tools` or Codex config override as break glass: those existing defer paths must either be rejected under managed mode or normalized into the same explicit, bannered, audited record.

# Rollout sequence and observability

1. Land the explicit break-glass option, local record/replay, teaching banner, and both drills.
2. Finish the capability PTY/background completion work and make the chosen sandbox posture observable.
3. Run the P-017 parity suite green on each supported client/version and on resume/wake paths.
4. Ship prompt/tool guidance that names `capability:bash`, `capability:bash_output`, and `capability:bash_kill` as the only managed command route. A denied native attempt must teach the same route.
5. Add adoption telemetry at the launch/tool-call boundary: client/version, native availability state, native attempt/denial count where observable, capability invocation count, operator-unavailable failures, background completion wake latency, spill rate, kill/timeout outcome, and break-glass activations.
6. Canary the managed disable on a small role cohort. Fail closed on parity regression, but use the explicit break glass for operator recovery. Expand only after the telemetry shows no native fallbacks, no stranded backgrounds, and no unexplained break-glass use.
7. Enable for all managed agents. Human-owned unmanaged terminals are outside D-016 unless separately opted into managed policy.

The feature flag is a staged rollout lever, not the safety mechanism. The end state is native command execution disabled for managed agents by default, with one explicit local break-glass route and no second hidden orchestration backend.

# Source and probe basis

The server-side claims were read from the files listed in this document's metadata and the P-001 ownership/reuse map. Claude disable behavior was proved with marker-file positive/negative controls plus one background completion/kill run; current alias normalization was confirmed in the installed 2.1.240 binary. Codex behavior was proved with JSONL `command_execution` presence/absence while holding `unified_exec=true`. OMP behavior was proved with marker-file positive/negative controls in an isolated profile; its installed type declarations confirm `cwd`, `env`, `pty`, `timeout`, `async`, streaming callback, abort signal, byte/line accounting, and artifact return shapes.
