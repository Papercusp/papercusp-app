## Live source of truth

This page is a snapshot. The runtime catalog is always at:

```bash
$ curl http://localhost:3070/api/plugins/tools | jq
```

…and visible in the dashboard at `/settings/plugins/tools`.

Every tool here is callable on **both** transports:

* **HTTP**: `POST /api/plugins/<...>` (plugin tools) or `POST /api/agent-tools/<...>` (built-ins)
* **MCP**: through the orchestrator-baked `.mcp.json` URL or the [superuser-mode](./superuser-mode) `?superuser=1` endpoint

## Built-in tools (\~633)

Tools registered via `defineTool`, primarily from `packages/operator-core/lib/agent-tools/` (read-side tools live in `packages/agent-mcp/src/tools/`). They run with a principal (bearer-resolved) and have direct PG access via `ctx.tx`. The runtime catalog (`.papercusp/tool-catalog.json`, generated by `scripts/gen-tool-catalog.ts`) reports **633** built-ins as of 2026-07-10 (this fleet adds tools continuously — re-run the generator or call `agent_tools:list` for the live count). This page is a hand-curated subset; for the full live grouping (every group → verbs → capabilities) see the generated **Tool catalog (grouped)** reference page (`reference/tool-catalog`, projected from the `defineTool` registry by `scripts/gen-doc-tool-catalog.ts`).

### `harness:*` (15)

List, get, status, plan reviews, phase paths, markdown index, escalation, health, list\_features, pending\_reviews, configure, create, generate-from-repo, membership, overview, etc. — read (and a few write) views into a workspace's harness state. (Doc-retrieval for a harness is **not** here — it lives on context-aware `docs:*`, or `cross_harness:docs_*` for explicit-slug queries from outside.) The 15 span three homes: `list`/`get`/`status` are read-side, registered from `packages/agent-mcp/src/tools/harness/`; 11 (`configure`, `create`, `escalation`, `generate-from-repo`, `health`, `list_features`, `markdown_index`, `membership`, `overview`, `pending_reviews`, `phase_path`) live in `packages/operator-core/lib/agent-tools/harness/`; and `harness:migrate-config-json` is registered under the `harness:` prefix from the deploy module, so a directory-only count of that last group looks like 12.

### `operator:*` (23)

The operator surface: `audit`, `budget`, `dedup_check`, `nudge`, `trigger_state`, `preview_prompt`, `decisions`, `preferences`, `multi_workspace` view, `credentials_status`, `paused` papercup, the standing-approval verbs (`standing_approvals_list` / `standing_approvals_decide` / `standing_approval_mark_shown`), and the voice/conversation verbs (`converse`, `conv_voice`, `voice_prefs`, `voice_debug`, `voice_spend_summary`, `voice_utterance_log`, `notes`, `stats`, `rate_limit_config`). (There is no `operator:scan`, `operator:dispatch`, `operator:scanner`, or (any longer) `operator:delegate` — names like those appear only in test files, prompt templates, and plan docs, not in the registry.)

### `messages:*` (4)

Cross-harness messaging: `inbox`, `outbox`, `send`, `dismiss`.

### `features:*` (5)

`get`, `history`, `search`, `list_related`, `tag_vocabulary`.

### `tasks:*` (3)

`list`, `get`, `create`.

### `roles:*` (4)

`list`, `get`, `firing_on`, `known`.

### `cross_harness:*` (10)

`inbox`, `outbox`, `supervisor_notes`, `recent_activity`, `docs_outline`, `docs_get`, `docs_search`, `plans_list`, `plans_get`, `plans_search` — the docs\_\* / plans\_\* variants take an explicit `harnessSlug` (and optional `workspaceId`) for engineers querying a specific harness from outside its context. See [docs retrieval](/internal/docs/agents/docs-retrieval).

### `docs:*` (4)

`outline`, `get`, `search` — **context-aware**: returns the caller's harness docs when `ctx.harnessSlug` is set, the Papercusp engineering reference otherwise. Backed by `@papercusp/docs-engine`. Plus `author` — the write-side counterpart (create a manual/agent-insights doc at the harness's canonical docs root, stamp frontmatter, and auto-anchor + verify it, closing the old read-only-docs-surface gap). See [docs retrieval](/internal/docs/agents/docs-retrieval).

### `projects:*` (4)

`list`, `get`, `spec_revision`, `spec_revisions`.

### `artifacts:*` (4)

`load`, `save`, `append`, `delete` — PG-canonical text artifacts (`harness_text_artifacts`).

### `plugins:*` (4)

`runtime_status`, `invoke_action`, `fire_event`, `tui_panes`.

### Pairs (2 each)

* `intel:*` — `spawn_tree`, `artifacts` (Intel panel data)
* `goals:*` — `list`, `get`
* `autoloop:*` — `status`, `control`

There is **no** `snapshots:*` group — full-workspace snapshot tooling lives under `backup:*` (e.g. `backup:snapshot_create`, `backup:snapshot_list`).

## Plugin tools (36)

In-repo plugins under `libs/papercusp/plugins/<name>/`. They run without a principal (URL-baked spawn context); gates: role allowlist, capability tier, per-window quota. The **(36)** here is a snapshot that mixes static manifest tools (repomix 1 + firecrawl 3 + code2prompt 2 + fetch-plus 1 + design-phase 12 + example-tool-pack 2 = 21), the dynamically-registered gitnexus bridge (13), and historical entries — so it drifts from the live runtime count. Several in-repo plugin dirs (`cloudflare-pages`, `cloudflare-stack`, `example-tui-pane`, `github-repo`, `markdown-preview`, `notion-export`, `pi-coding`, `postgres-manager`, `pythonista`, `slack-notifier`, `starlight`) currently ship **0** tools. ## How to invoke

### From an OMP shell ([superuser-mode](./superuser-mode))

```
omp> call mcp__papercusp-su__papercusp:list_workspaces
omp> call mcp__papercusp-su__gitnexus:list_repos
omp> call mcp__papercusp-su__repomix:pack with target_dir /tmp/some-repo
```

### From curl (HTTP transport)

```bash
TOK=$(cat ~/.papercusp/superuser-token)

# Plugin tools — under /api/plugins/<plugin>/<tool>
curl -X POST "http://localhost:3070/api/plugins/repomix/pack?superuser=1&workspace=default&harness=sheets" \
  -H "Authorization: Bearer $TOK" -H "Content-Type: application/json" \
  -d '{"include":["README*"]}'

# Plugin tools — wildcard workspace (per-call ?workspace= override or arg)
curl -X POST "http://localhost:3070/api/plugins/gitnexus/list_repos?superuser=1" \
  -H "Authorization: Bearer $TOK" -H "Content-Type: application/json" -d '{}'

# Built-in tools — under /api/agent-tools/<group>/<verb> (require principal bearer, not superuser bearer)
curl -X POST "http://localhost:3070/api/agent-tools/intel/spawn_tree" \
  -H "Authorization: Bearer <principal-bearer>" -H "Content-Type: application/json" \
  -d '{"harness":"sheets","limit":10}'
```

### From MCP transport

```bash
curl -X POST "http://localhost:3070/api/mcp?superuser=1" \
  -H "Authorization: Bearer $TOK" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"papercusp:list_workspaces","arguments":{}}}'
```

## Discovering schemas at runtime

Every tool's `inputSchema` is JSON Schema (Zod 4 → `z.toJSONSchema`). Browse them:

```bash
$ curl -s http://localhost:3070/api/plugins/tools | jq '.tools[] | {name, inputSchema}'
```

Or pretty-printed in the dashboard at `/settings/plugins/tools`.
