# Papercup chat — feature parity matrix (acceptance baseline)

Plan `papercup-chat-one-component-one-contract-2026-09-06`, item **P-002**. One row per
renderer / behaviour on each side of the two Papercup chats that exist today, with the
disposition each one gets when the two converge into ONE shared component
(`PapercupChat` + `usePapercupChat` in `@papercusp/operator-ui`, D-003) speaking ONE
backend — **converse's conversation model** (`operator_conversations` +
`/api/operator/conversations/:id/turns` + `POST /api/agent-mcp/operator-converse`),
integrated behind the portal's per-user boundary (D-007, owner-ratified 2026-09-06,
revising D-002/D-004's agent-chats choice).

**This table is machine-checked** by `parity-matrix.test.ts` beside it (parser:
`parity-matrix.ts`): a named source symbol that disappears without this file changing
fails the guard; a `retired` symbol that comes back fails it; a `ported` row whose target
is missing fails it; the D-005 trust invariants on the `md-*` rows are asserted
explicitly. Change the code and this table **in the same change**.

## How to read a row

| column | meaning |
|---|---|
| `id` | stable slug; `op-*` operator side, `pt-*` portal side, `sh-*` already shared, `md-*` markdown features (D-005) |
| `side` | where the behaviour lives TODAY: `operator` (papercusp desktop/`:3055`), `portal` (`:3081` shell), `shared` (`libs/generic/*`, or a contract both will use) |
| `source` | `` `repo/path#Symbol` `` — the code that implements it now. `repo` is `papercusp` (this monorepo) or `portal` (the sibling checkout `../portal`, or `PAPERCUP_PORTAL_ROOT`). `#"quoted text"` is a literal marker instead of an identifier. |
| `disposition` | `keep` · `port` → `ported` · `retire` → `retired` · `open:P-NNN` — see the grammar in `parity-matrix.ts`. **Final state for ship (P-013): only keep / ported / retired remain.** |
| `trust` | `md-*` rows only: what the shared renderer does on the PUBLIC host vs the OWNER host — `render` · `inert` (shown as plain text) · `off` · `opt-in` (host must enable) · `allowlist` (URL-scheme allowlist, D-005) |
| `target` | for port/ported rows: where it lands. Names under `packages/operator-ui/src/papercup-chat/` are the planner's proposal until P-007 lands — fix the cell when you flip the row to `ported`. |
| `reason` | the one-line why, with its source decision where one governs it |

Disposition rules applied (from the plan's decisions): D-001 the portal-facing component
survives and the operator's sidebar chrome stays as the desktop's "small tweak" around it;
D-007 (owner-ratified, revising D-002/D-004) keeps converse as the ONE backend and ports the
agent-chats seam's Papercup-only gains INTO it — the per-user boundary, a host-trust-keyed toolset,
the memory / UI-context / dossier / plan-context prompt sections, and the quick-model + deep-brain
pin (`gpt-5.6-luna:low` on codex for testing, per the owner) — while D-006 records P-003's
per-behaviour rulings as revised by D-007; D-003 chat-protocol / chat-cards stay the wire
and card layers; D-005 the stricter (public) security rule wins on BOTH hosts for HTML and
links, and `owner` trust may widen tables/images only. Rows whose disposition is the
planner's own judgment rather than a decision's letter are tagged `[inferred]` in the
reason — challenge them at P-013 review.

## Maintaining it

- **Renaming or deleting a source symbol?** Update its row in the same change (the guard
  names the row and line). `retire` → `retired` when you delete a duplicate; `port` →
  `ported` when you land a move, fixing the `target` cell to the real name.
- **Adding a chat behaviour on either side?** Add a row. A behaviour with no row is
  invisible to the P-013 audit.
- **Portal rows** need the sibling checkout (`../portal`, or `PAPERCUP_PORTAL_ROOT`); without
  it they are reported as *skipped*, never passed.
- **Run:** `testing:run { files: ['packages/operator-ui/src/papercup-chat/parity-matrix.test.ts'] }`
  or `npm run test:file -- packages/operator-ui/src/papercup-chat/parity-matrix.test.ts`.
