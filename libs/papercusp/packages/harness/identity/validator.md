# IDENTITY — validator

This file is your durable, cross-mission memory. Curator maintains it (append-only). You read it at startup to carry forward lessons from prior missions that the current mission's `.papercusp/memory/summary.md` doesn't capture.

## Patterns I've learned

- [2026-04-25] Real `page.keyboard.press` (CDP) reveals input races that synthetic events inside `page.evaluate` mask — yielding between keystrokes hides startEdit-style races. Use real keyboard for *correctness*; use `page.evaluate` for *perf* (CDP IPC ~18ms per round-trip dominates 100-edit loops, masks browser-side speed).
- [2026-04-25] To validate `beforeunload`/`pagehide` handlers without actually unloading: patch `navigator.sendBeacon` (or fetch) on the page to record calls, then fire the trigger event + `window.location.reload()` in ONE `page.evaluate` for deterministic <2ms unload after commit. Pair with a server-side `curl GET` to confirm persistence.
- [2026-04-25] Playwright MCP Chromium quirks: `browser_snapshot` omits absolutely-positioned virtualized DOM nodes (no text/role extracted); `clipboard-read` stays `'prompt'` (only `clipboard-write` is granted), so `navigator.clipboard.readText()` rejects silently. Prefer `npx playwright test` against throwaway specs over coord-driven MCP clicks; monkey-patch `navigator.clipboard.{writeText,readText}` via `page.evaluate` to test paste handlers.
- [2026-04-25] When validating a fix for an "input X is silently coerced to type Y" bug, ALWAYS probe adjacent input shapes immediately (other separators, surrounding whitespace, lowercase variants, leading-symbol prefixes). Regex-narrow fixes pass for the original report and leave the bug class live in everything that wasn't explicitly tested — F-FIX-016 fixed `1.2.3` only; `1-2-3` and `1/1/2020` still mutated user text on the same code path. The validator owns this probe because the worker's tunnel vision is exactly what produced the narrow fix.

## Failures I've seen

- [2026-04-25] Bind-mounted source + uvicorn (or any framework) without auto-reload ⇒ the live endpoint serves stale code after a worker edit. Always check container `StartedAt` vs source `mtime` when "code looks right but behavior is old"; restart the container before re-probing. Bit one mission ≥3 times across consecutive features before being captured.

## Context shortcuts

- [2026-04-25] Default `tsc --noEmit` / plain `mypy` may silently skip files based on `tsconfig.json` `include` and `pyproject.toml [tool.mypy] files`. Always invoke with widened scope (e.g. a tsconfig.e2e.json for specs, `mypy <pkg>` from repo root) — what a contributor runs locally is not necessarily what the build gate should be.

- [2026-05-08] `page.clock.install()` must be called BEFORE `page.goto()` to fake `setInterval`s registered during component mount (e.g. presence-stale, cursor-blink, debounced-save timers). Calling it after navigation leaves the already-registered timers running on real time and the fake-clock test silently passes-by-luck or hangs. Evidence: F-COLLAB-002 validator (sheets-clone).
- [2026-05-08] When the harness's status-write API is broken (RLS, auth, transport), stdout return values become the only reliable status channel — every role downstream reads them. Keep validator stdout structured (`PASS`/`FAIL`/`PARTIAL` + per-claim list); don't rely on a successful PATCH to `/api/harness/.../features/<id>` reflecting your verdict. Evidence: F-COLLAB-002, F-COMMENT-001 (sheets-clone PATCH-500 RLS issue).
- [2026-05-08] Any "populate from CSV/paste/import/external-file" feature has silent-truncation past grid bounds as its default failure mode. The validator must add an overflow probe (payload exceeding both axes) — banner-on-overflow should be a contract requirement, not a bonus. Evidence: F-CSV-002 (I-0073), F-013 TSV (I-0049).
- [2026-05-08] Forward-feature dependencies in a validation contract (e.g. comments must survive sort/struct ops, but SORT/STRUCT are still `todo`) are NOT failures of the parent feature. Verify core claims, file the deferred clauses as `minor`/`major` issues with `foundDuring=<parent>`, and document them as Limitations on the feature's docs page. Failing the parent for absent dependencies blocks the queue. Evidence: F-COMMENT-001 (I-0076).
- [2026-05-31] A harness's assertion-resolution API can be entirely UNMIGRATED: `GET /api/harness/<slug>/assertion/VAL-*` returns `assertion_not_found` for EVERY id, including features that already passed. If your verdict pipeline treats a step-2 404 as a hard-FAIL you will false-fail every feature. Diagnostic: if the lookup also 404s for an *already-passed* feature, the API is the broken thing, not the feature under test — fall back to the on-disk `.papercusp/validation-contract.md` (authoritative) and file the gap as an infra issue rather than failing. Evidence: F-FIX-027 (sheets-clone, I-0101).
- [2026-06-03] **Gym/sandbox harness implicit-assertion fallback:** Gym harness runs create features with `claims=null` and register NO plan assertions — the assertion-resolution API returns `assertion_not_found` for every ID by design. Do NOT treat this as a hard-FAIL or infra bug. Instead: derive 2–3 implicit assertions from the feature summary prose (e.g. "returns 200 for /health, 404 otherwise"), run them against the test suite, and report results directly in `issues.md`. File the missing-claims infrastructure as a minor out-of-scope observation, not a blocker. Evidence: F-GYM-A02F4A66 (gymbaseline).
- [2026-06-03] **Unregistered harness: file findings to `.papercusp/pending-issues.jsonl` as local fallback.** When both the status PATCH (`PATCH /api/harness/<slug>/features/<id>`) AND the append-pending POST (`POST /api/harness/<slug>/issues/append-pending`) return `{"error":"unknown project"}`, write structured findings as JSONL to `.papercusp/pending-issues.jsonl` — one JSON object per line with fields: title, severity, foundDuring, evidence, repro, suggestedFix, codePointer. This preserves machine-readable triage data the curator can absorb even though it cannot formally merge them while the harness is unregistered. Evidence: F-GYM-A02F4A66 (gymcandreadback02b63646d1b).
- [2026-06-02] **ESM inline spot-check technique:** `node --input-type=module -e "import { fn } from './index.js'; ..."` probes an ESM handle-function sub-second with no server, no test runner, and no npm install. Batch multiple edge-case probes (null req, undefined path, trailing-slash variant, empty string) in a single inline script — it's faster than spinning up a test runner for quick black-box checks. Evidence: F-GYM-99DE522A validator (gymbaseline013f2767a19).
- [2026-06-05] **Gym/sandbox harness test invocation: run with `node index.test.js` (plain script), NOT `npx jest`, `vitest`, or `npm test`.** These harnesses have no 'test' script in package.json — check before reaching for npx. The file uses `node:test` internally but is invoked directly. Evidence: F-GYM-A02F4A66 (gymbaseline075005915be).
- [2026-06-03] **Probe `handle(null)` as a standard edge case for any request-handler function.** When no null guard is present, `req.path` throws `TypeError: Cannot read properties of null (reading 'path')`. This is the predictable failure mode for simple dispatch functions across gym baselines. Always include it in your edge-case probe batch alongside empty-string path and undefined path. Evidence: F-GYM-67DB4E55 (gymbaseline09f2b3309f1).
- [2026-06-11] **`gym_judge` MCP tool returns `missing_capability` for `system:validator` role** — absent in gym harnesses by default. Do not flag it as a gap or error. Fall back to: (1) `node --test <file>` for the test suite, (2) `node --input-type=module -e "import {fn} from './index.js'; ..."` for inline edge-case probes. Write all findings to `issues.md` + `pending-issues.jsonl`. This is the complete, correct fallback chain — treat it as non-degraded. Evidence: F-GYM-67DB4E55 (gymbaseline09f2b3309f1, 2026-06-11).
- [2026-06-12] **When both harness API AND PG are inaccessible, derive implicit assertions from the git commit message prose** — not just feature summary. Commit format `chunk[F-xxx]: <description>` reliably encodes the feature's claims; each clause maps to a VAL assertion ("add /health endpoint returning 200 ok" → VAL-1: returns 200, VAL-2: body is 'ok'). Assertion-source priority: (1) API feature summary, (2) PG `harness_features.summary` via `HARNESS_ADMIN_DATABASE_URL`, (3) git commit message. Evidence: F-GYM-99DE522A validator (gymbaseline013f2767a19, 2026-06-12).
- [2026-06-13] **Probe query-string and trailing-slash path variants for any exact-string router.** `handle({ path: '/health?foo=bar' })` and `handle({ path: '/health/' })` return 404 in a handler that does `req.path === '/health'` — no stripping occurs. Include both in every edge-case batch alongside `handle(null)` and empty-string path. Evidence: F-GYM-99DE522A (gymbaseline013f2767a19).
- [2026-06-15] **Pure-stub null-guard rule:** when `handle()` never dereferences `req` (grep `req\.` in the handler shows zero hits), `handle(null)` is safe by construction. Still run the edge-case probe batch to confirm, but record "safe by construction" rather than filing an OOS null-guard issue. Contrast: if `req.path` or `req.method` appears in the source, the null-guard probe remains mandatory. Evidence: F-GYM-99DE522A (gymbaseline013f2767a19, 2026-06-15).
- [2026-06-17] **`handle({path:undefined})` is safe for unconditional `req.path` access — null is the only crash vector.** `undefined` coerces to string `'undefined'` which does not match any route (e.g. `/health`), so the handler falls through to the default 404 branch. Always add `handle({path:undefined})` to the edge-case probe batch alongside `handle(null)` — it confirms the coercion safety and is distinct from the null crash. Evidence: F-GYM-99DE522A validator (gymbaseline013f2767a19, 2026-06-17).
- [2026-06-17] **When handler dereferences `req.method`, BOTH `handle(null)` AND `handle(undefined)` crash** — not just null. The safe-coercion note above applies ONLY to `req.path`-only handlers. With `req.method`, `undefined.method` throws `TypeError: Cannot read properties of undefined (reading 'method')` just like `null.method` does. Pattern: `grep 'req\.method'` in the source; if present, probe `handle(null)` AND `handle(undefined)` separately and expect both to throw without a null guard. Evidence: F-GYM-99DE522A (gymbaseline013f2767a19, 2026-06-17) — handler `req.method === 'GET' && req.url === '/'`; both probes threw TypeError.
- [2026-06-19] **When handler uses `req && req.path` short-circuit guard, BOTH `handle(null)` AND `handle(undefined)` safely return 404 — no TypeError.** The `req &&` prefix short-circuits falsy req before any property access, covering null and undefined equally. Update probe interpretation: if you see this guard pattern in the source, expect safe 404 for both crash-candidates and record "safe by guard, not by construction" (distinct from the pure-stub case). Evidence: F-GYM-99DE522A (gymbaseline013f2767a19, 2026-06-19) — `index.js:2`: `if (req && req.path === '/health')`; `handle(null)` → 404, `handle(undefined)` → 404, confirmed by validator + curator grep.
