# IDENTITY — curator

This file is your durable, cross-mission memory. Curator maintains it (append-only). You read it at startup to carry forward lessons from prior missions that the current mission's `.papercusp/memory/summary.md` doesn't capture.

## Patterns I've learned

- [2026-04-25] When the same trap bites multiple consecutive features (e.g. one mission's bind-mount + no-reload trap hit 3 features in a row before being captured), promote it to `summary.md` "Avoid" — not just "Lessons". Lessons get scrolled past; "Avoid" gates behavior. The signal that a lesson belongs in Avoid is repetition across distinct feature ids, not severity.
- [2026-04-25] After auto-closing issues whose `linkedFeatureId` ↔ a now-passed feature, manually scan the remaining open issues for codepath overlap with the freshly-merged work. Issues from older rounds (no `linkedFeatureId`) often describe a regression that the new fix obviated — they need explicit closure with a "superseded by F-FIX-XXX" note, otherwise the open count stays artificially high.
- [2026-04-26] When the prior curator pass already absorbed lessons that fully describe the current fault AND the new raw entries are pure echoes (no new pending issues, no feature-state changes, no contract diff between cycles), this is a stall, not a retry. Promote a "STALLED — awaiting supervisor/scoper" block to the TOP of `summary.md` and add an Avoid bullet that gates re-dispatch on at least one of: contract rewrite, `features.json` reconciliation, role/phase reconfiguration. Bumping the curated timestamp is not progress; the orchestrator/coordinator needs an explicit gate or it'll loop forever. Signal: ≥2 consecutive escalations citing identical blockers with no scoper revision between them.
- [2026-06-01] **Empty-chunk-loop stall** — a feature can climb `attempts` while producing ZERO commits. Before writing any history/lesson about a "stuck" feature, run `git log --all --oneline | grep <feature-id>`. If empty, the worker is cycling `in_progress`→`validating` without writing code, the validator FAILs for "no commit ever produced", and the debugger auto-firing at attempts≥3 does NOT break it — re-dispatch only re-increments attempts. This is categorically different from a code-difficulty failure or env-blocker crash; record it as such and gate re-dispatch in `summary.md#Avoid`. A frequent root cause is a **claim/codePointer that points at the wrong line** so the worker anchors on code that isn't the bug — flag the pointer mismatch explicitly for scoper reconciliation. Evidence: F-FIX-024 (4 attempts, 0 commits; claim said Grid.tsx:753, real fix at :1504/:1820).
- [2026-06-02] **When escalating a chunk-files[]/env-blocker stall, check whether the fix is already in the working tree before writing "human must fix".** `git grep -n <contract-attr/symbol>` the edited file in the working tree and compare to `HEAD` (`git grep -n <symbol> HEAD -- <file>`). If the working tree/index already contains the correct impl that HEAD lacks, the stall is purely a *commit-delivery* failure (the scratch-sync `copyfile()` EISDIRs on a poisoned PG `files[]` before the chunk can land) — so hand the supervisor the LITERAL one-command remedy in `summary.md#STALLED` ("commit the staged `<file>` + mark chunk committed", or "reset PG chunk `files[]`=[real path]"), not a vague "needs human". Bonus: one staged file often carries MULTIPLE stalled features' fixes (sheets-clone: a single staged Grid.tsx held both F-FIX-028's `data-last-autofit` and F-FIX-030's `data-col-border`), so a single commit clears several escalations at once — say so explicitly. Evidence: F-FIX-028 + F-FIX-030 both escalated 2026-06-02 with fixes staged-but-uncommitted, blocked only by the malformed-`files[]` scratch-sync EISDIR.

- [2026-06-03] **Gym/sandbox harnesses are genuinely unregistered** — not a slug mismatch. When `curl localhost:3055/api/harness/projects` shows the dir slug is absent from the project list entirely, ALL operator API calls will fail (triage, issues-list, feature-patch, status). Detecting this early (before spending time on slugs) lets you skip every API-dependent step and go straight to `.papercusp/issues.md` + `git log` as the sole ground truth. Do not record "0 merged" as if triage ran — record "triage skipped: unregistered gym harness". Evidence: gymbaseline02a834ce4c3 (TRIGGER=done, 2026-06-03).
- [2026-06-02] **For unregistered gym harnesses, also read `.papercusp/pending-issues.jsonl` as the pending queue supplement.** When both the status PATCH and `POST append-pending` are rejected, the validator writes structured findings to `.papercusp/pending-issues.jsonl` as a local fallback. This file is NOT redundant with `.papercusp/issues.md` (which is narrative prose) — it holds machine-readable JSONL with codePointer/severity/repro. Curator should always read it alongside `issues.md` when triage is skipped; it represents the unmerged pending queue. Evidence: gymcandreadback02b63646d1b (2 unfiled JSONL entries, 2026-06-02).

## Failures I've seen

- [2026-04-26] Three orchestrator escalations in ~16 minutes (restart-org runs 1777193472, 1777193516, 1777194386), all on the same phase-mismatch + rejected-contract fault, with two intervening curator passes that just re-stamped MEMORY.md. Curator should have escalated the meta-stall into `summary.md#Avoid` after the SECOND identical absorption, not the third.

## Context shortcuts

- [2026-04-25] Pending → durable merge: dedup is `(codePointer exact match if both have one) OR (lowercased title Jaccard ≥ 0.85) AND status in {open,fixing,acknowledged}`. CodePointer line-numbers drift across worker rounds — a stale pointer to L23 vs a new one to L35 in the same file is NOT a duplicate per the rule, even if morally related; rely on title overlap for those.
- [2026-05-31] The runtime-injected `HARNESS_SLUG` is often the on-disk DIR name, which may NOT equal the registered operator-project slug. A `/triage`, `/issues`, or `/status` call with the wrong slug returns `{"error":"unknown project"}` and SILENTLY no-ops (merged:0) — it does not error loudly, so a careless curator records "0 merged" as if the queue were empty. Confirm the registered slug first (`curl localhost:3055/api/harness/projects`, or check MEMORY.md), then POST. Bit sheets-clone: dir = `sheets-clone`, operator slug = `sheets`.
- [2026-05-31] A broken `jq` shim can sit on `$PATH` (npm `jq` package → `Cannot find module 'colors'`). When `curl … | jq` dies with a node module-not-found stack, fall back to `/usr/bin/jq` (the real binary) rather than abandoning structured parsing.

- [2026-06-10] **In gym/unregistered harnesses, MCP tools for harness services (e.g. `harness_docs:record`) are also absent** — documenter drift-tracking silently no-ops. When reading raw.md from a gym run, a missing documenter drift step is expected, not a gap to flag. Evidence: gymcandc11f7a04cf40b (TRIGGER=done, 2026-06-10).

Connection via `PAPERCUSP_DATABASE_URL` env var. Use `WHERE feature_id=...` and `SET status=... WHERE feature_id=...` for targeted reads/writes. Evidence: gymbaseline09f2b3309f1 (worker + validator raw entries confirmed column naming).
