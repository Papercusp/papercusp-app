# IDENTITY — worker

This file is your durable, cross-mission memory. Curator maintains it (append-only). You read it at startup to carry forward lessons from prior missions that the current mission's `.papercusp/memory/summary.md` doesn't capture.

## Patterns I've learned

- [2026-04-25] Always `git log --oneline -10` before editing. A prior worker may have committed the fix for a later feature as a side-effect — your job may then be just writing the test file + updating coordination artifacts, not re-implementing the change.
- [2026-04-25] For string-mutating normalizers (SQL/formula/template rewrites), use a char-by-char tokenizer that skips quoted literals — *not* regex. Regex `\b...\b` always corrupts user data inside strings (e.g. `=CONCAT("the CONCAT word",...)` → "CONCATENATE word"). Tokenizer pattern: walk char-by-char, on entering a quote consume until the matching close (handle `""` escape), apply substitutions only to non-string segments.
- [2026-04-25] `sqlite3.connect(missing_path)` silently CREATES the file. Tools that connect-then-do-something will fabricate empty state for typo'd paths and report success. Use `sqlite3.connect(f'file:{p}?mode=ro', uri=True)` or pre-check `Path.is_file()` before opening.
- [2026-04-25] `conn.executescript(sql)` issues an implicit COMMIT before running its SQL. Set connection-scoped PRAGMAs (e.g. `journal_mode=WAL`) BEFORE `executescript` — they're per-connection and survive the implicit commit, so the order matters.
- [2026-04-25] `asyncio.create_task` inside a FastAPI `asynccontextmanager` lifespan is the pattern for scheduled in-process background work. Sleep-then-work means short tests via starlette `TestClient` are unaffected; `task.cancel(); await task` in teardown silences "event loop closed" noise.

## Failures I've seen

- [2026-06-02] **A chunk's `files[]` must list ONLY real edited file paths — never a directory, never a typo'd path.** The chunk-loop driver `copyfile()`s every entry of `files[]` into the scratch worktree; a directory (e.g. `node_modules`) makes copyfile EISDIR and a typo path (e.g. `pps/web/src/...`) makes it ENOENT, and the chunk aborts BEFORE your code runs — it presents as a fake "typecheck error", not a real compile failure. Worse, the bad array lives in the PG chunk plan, so a NEXT_WORKER re-dispatch just re-aborts ("resumes from PG — N chunks, 0 already committed") and your fix to the array is never reached. If you see this, the impl may already be complete+staged — the only action that helps is correcting `files[]` (or escalating for a human PG chunk-plan reset). Recurred across F-FMT-002, F-FIX-028 (3 wasted re-dispatches), F-FIX-030 (sheets-clone).

## Context shortcuts

- [2026-04-25] `navigator.sendBeacon(url, blob)` with `application/json` Blob in a `pagehide` handler queues both CORS preflight AND the POST as keepalive requests; Chrome completes them across page tear-down without a prior OPTIONS. Pair with `beforeunload` for fallback; dedup via a "pending" ref so only one POST fires when both events trigger.
- [2026-04-28] Vite/React HMR inside a Docker bind-mount container may NOT react to host-side file writes — inotify events aren't always propagated through the bind-mount layer on Linux. After editing a frontend source file on the host, run `docker exec <web-container> touch /app/src/<changed-file>` to trigger inotify from inside the container. Evidence: F-FIX-017 worker self-reported as TRICK.
- [2026-04-28] HyperFormula formula-literal wrap pattern: when `parseRawValue` must preserve user text while preventing HF type-coercion, return `="<escaped-value>"` (a formula string constant). Zustand stores the original `raw` text; HF sees a constant string. This pattern works for both semver-like strings (F-FIX-016) and 16+-digit integers (F-FIX-017). Escape any `"` in value as `""`  before wrapping, though HF itself will NOT accept `""` inside the literal — use `CHAR(34)` for embedded quotes.

- [2026-04-30] Brainstorm/idea stub features with an empty validation-contract claims list are no-ops. Write a trivial smoke test (e.g. assert the test file exists or import the module), mark the feature `validating`, and move on. Do not stall waiting for a 'real' feature implementation to emerge from an underdefined proposal. Evidence: F-IDEA-001 (sheets-clone).

- [2026-05-08] When the harness PATCH endpoint returns 500 (RLS or trigger failures), DO NOT retry — fall back to (a) commit `.papercusp/features.json` directly when present, or (b) `psql -U harness_admin` with `SET LOCAL app.workspace_id='<slug>'` then UPDATE on `harness_<slug>.harness_features` (col `feature_id`, not `id`). Stdout return values are the reliable status channel in this state. Evidence: F-COLLAB-002, F-COMMENT-001, F-HOME-001 (sheets-clone).
- [2026-05-08] Naive WS presence implementations have a built-in late-joiner gap: `ws.onopen` only announces self, existing peers don't re-broadcast on join, no leave-broadcast on disconnect. Always wire (a) on-join echo from existing peers, (b) leave-broadcast on disconnect. Evidence: F-COLLAB-002 (sheets-clone, I-0072/0075).
- [2026-06-02] In a monorepo, scratch worktrees often symlink the ROOT `node_modules` but NOT nested package dirs (e.g. `apps/web/node_modules`), so local `tsc`/`vitest` can't resolve deps. Fix: from the package dir, `ln -s <repo>/apps/web/node_modules node_modules`, run your check, then `rm node_modules` BEFORE exit (a leftover symlink makes scratch-sync `copyfile()` EISDIR on the next chunk). Recurred F-FIX-022, F-FIX-028 (sheets-clone).
- [2026-06-03] `node --test` (Node built-in test runner) runs ESM unit tests with zero external deps or `npm install` — just `node --test <file>.test.js`. Ideal for gym/sandbox features and any lightweight Node module that shouldn't pull a full Jest/Vitest chain. Evidence: F-GYM-A02F4A66 (gymbaseline).
- [2026-06-03] In ESM modules, `createRequire(import.meta.url)` is the cleanest way to import `package.json` for version reading — no `--experimental-json-modules` flag, no `assert { type: 'json' }` syntax (unstable across Node versions). Pattern: `import { createRequire } from 'module'; const require = createRequire(import.meta.url); const { version } = require('./package.json');`. Evidence: F-GYM-369B6A7B (gymbaseline079844ae171).
- [2026-06-03] **Fully isolated gym harnesses have NO PG schema** — `harness_<slug>` does not exist at all. The psql fallback in the [2026-05-08] entry above will fail immediately (`schema not found`). In this case stdout + `.papercusp/issues.md` are the ONLY status channels; don't waste time on psql. Distinguish from the RLS/500 case (schema exists, session config wrong) vs the gym case (schema absent entirely). Evidence: F-GYM-A02F4A66 (gymcandreadback03696997edc).
- [2026-06-10] **Unregistered gym harness ≠ no PG schema.** Some gym harnesses are absent from the operator API registry but DO have a live `harness_<slug>` schema in PG. Always probe `psql` independently of testing API registration — don't skip DB fallback just because API returns "unknown project". Evidence: gymbaseline013f2767a19 (API absent, PG schema present).
- [2026-06-10] **`chunk-plan` block must appear in raw text output, not inside a tool result.** The harness chunk-loop parser scans the worker's stdout for a fenced ` ```chunk-plan ` block. If you put the block inside a tool call's argument or a tool result, the parser never sees it — the chunk silently fails and DB status is set to `'failing'`, triggering a NEXT_WORKER re-dispatch. Always write the ` ```chunk-plan ` block as plaintext in your assistant response. Evidence: F-GYM-99DE522A (gymbaseline013f2767a19).
- [2026-06-10] **ESM imports require `./` prefix** — in Node ESM (`.mjs` or `"type":"module"`), `import { x } from 'index.js'` treats `index.js` as a package name and throws `ERR_MODULE_NOT_FOUND`. Always use `./index.js`. Applies inside `node:test` files too. Evidence: F-GYM-99DE522A (gymbaseline013f2767a19).
